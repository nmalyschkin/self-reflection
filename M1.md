## M1 — MVP core (ship this first)

Goal: Smallest usable app where a user writes a reflection and gets an AI-generated summary and leading questions. Minimal history (view-only) and minimal styling.

Definition of Done

- [x] Vite + React + TypeScript scaffold with ESLint/Prettier configured
- [ ] Single page UI with: textarea input, "Summarize" button, AI output (summary + questions)
- [ ] Chrome Prompt API integrated with feature detection and a friendly fallback message when unavailable
- [ ] Entries saved to localStorage; minimal, view-only history list on the same page
- [ ] Tailwind basic setup and minimal styles applied

Prerequisites

- [ ] Node.js 18+ and pnpm or npm installed
- [ ] A new empty repository initialized (git init)

Step-by-step Tasks

- [x] 1. Initialize project
  - [x] Run: `pnpm create vite@latest self-reflection --template react-ts` (or `npm create vite@latest`)
  - [x] `cd self-reflection`
  - [x] Install deps: `pnpm install`
  - [x] Add ESLint/Prettier: `pnpm add -D eslint prettier eslint-config-prettier eslint-plugin-react eslint-plugin-react-hooks @typescript-eslint/parser @typescript-eslint/eslint-plugin`
  - [x] Create `.prettierrc` (using flat `eslint.config.js` instead of `.eslintrc.cjs`)
  - [x] Add scripts in `package.json`: `lint`, `format`, `dev`, `build`, `preview`

- [x] 2. Add Tailwind CSS
  - [x] Install: `pnpm add -D tailwindcss postcss autoprefixer`
  - [x] Init: `tailwind.config.js` and `postcss.config.js`
  - [x] Configure `tailwind.config.js` content paths to include `index.html`, `src/**/*.{ts,tsx}`
  - [x] Add Tailwind directives to `src/index.css`: `@tailwind base; @tailwind components; @tailwind utilities;`
  - [x] Verify styles by adding a simple Tailwind class (e.g., `className="p-4 max-w-xl mx-auto"` on the root container)

- [x] 3. Implement app state (local storage, minimal)
  - [x] 3.  Implement app state (local storage, minimal)
  - [x] Define a TypeScript type for an entry: `{ id: string; text: string; createdAt: string; aiSummary?: string; aiQuestion: string }`
  - [x] Implement a small helper to read/write an array of entries in `localStorage` under a single key (e.g., `self.entries.v1`)
  - [x] On app load, parse storage JSON safely and default to `[]`

  - [x] 4. Build single page UI
    - [x] Start screen with button `Start reflecting` and reflection history
    - [x] Reflection page: textarea (reflection input), actions row. User text and AI text should be displayed similar to a chat (alligned on the left). Make the AI text be distinguishable by italic font.
    - [x] Textarea: multi-line input with placeholder; controlled by React state
    - [x] Actions row: `Save` button (primary) (finishes the reflection), `Deeper reflection` button (simulate interaction with AI. for now use "what's next" as AI response as a placeholder)
    - [x] AI output panel: shows last generated summary and questions for the current input
    - [x] History list (view-only): a simple list of past entries showing first line and created date; clicking an item loads it into the textarea and AI output (no edit persistence yet)

- [ ] 5. Integrate Chrome Prompt API
  - [ ] Feature-detect `LanguageModel` (Prompt API): check that `'LanguageModel' in window`
  - [ ] On a user gesture (click/keypress), call `await LanguageModel.availability(options)` with the SAME options you will pass to prompting; if status is `downloadable`/`downloading`, let Chrome fetch the model
  - [ ] When `LanguageModel` is not available block the UI and don't let users generate reflections
  - [ ] When `LanguageModel` is `downloadable` but not `available`, let the user start a reflection but indicate the progress of the model download in the right upper corner
  - [ ] Create a session with `const session = await LanguageModel.create(options)`; then call `await session.prompt(...)` with a concise prompt that:
    - [ ] Summarizes the user text (3–5 sentences)
    - [ ] Produces 3–5 compassionate, open-ended questions
    - [ ] While AI is processing block the action bar and indicate waiting for the AI response
  - [ ] Parse the string result and update `aiSummary` and `aiQuestions`
  - [ ] If unavailable, show an inline, non-blocking message: "On-device AI not available in this browser. You can still write and save reflections."
  - [ ] Optional: support streaming via `session.promptStreaming(...)` and cancellation via `AbortController`

- [ ] 6. Save flow
  - [ ] `Save` button creates a new entry with `id` (uuid or timestamp), `text`, `aiSummary`, `aiQuestions`, `createdAt`
  - [ ] Push to in-memory array and also write to `localStorage`
  - [ ] History list should update immediately

- [ ] 7. Minimal styling
  - [ ] Apply Tailwind utility classes for spacing and readability
  - [ ] Ensure mobile-friendly layout (stacked, full width)

- [ ] 8. Manual QA
  - [ ] Can type in textarea, click Summarize, and see AI results (or fallback message)
  - [ ] Can Save, and the history list shows the new entry
  - [ ] Reloading preserves the history (localStorage)
  - [ ] Clicking an item in history loads its content into the textarea and output panel
  - [ ] Lint passes: `pnpm run lint` and formatting `pnpm run format`

- [ ] 9. Final verification
  - [ ] All "Definition of Done" items are checked
  - [ ] Manual QA scenarios pass on desktop and mobile viewport
  - [ ] README reflects MVP status; open follow-up issues if needed
  - [ ] Commit and tag release (e.g., m1-mvp) or write release notes

Notes

- Keep prompts short and safe; prefer neutral tone
- Avoid heavy dependencies; keep bundle small for MVP
