## M3 — Installable offline app (+ Entry details & Regenerate AI)

Goal: Make the app a PWA that works offline and is installable. Add a dedicated entry details view and a "Regenerate AI" action using the Prompt API.

Definition of Done

- [ ] App has a Web App Manifest with icons and name
- [ ] Service Worker added (Workbox) with basic caching strategies
- [ ] App is installable; offline read and create work
- [ ] Entry details page with its own route
- [ ] Regenerate AI action on details page re-runs summary/questions

Step-by-step Tasks

- [ ] 1. Routing and details page

  - [ ] Install react-router if not present: `pnpm add react-router-dom`
  - [ ] Add route `/:entryId` for entry details
  - [ ] Details page shows full text, summary, questions, created date
  - [ ] Actions: `Regenerate`, `Save`, `Back to list`

- [ ] 2. Regenerate AI

  - [ ] Reuse feature detection; if unavailable, disable the button with tooltip
  - [ ] On click, call Prompt API with the entry text; update `aiSummary` and `aiQuestions`
  - [ ] Persist the updated entry via the store

- [ ] 3. Add Manifest

  - [ ] Create `public/manifest.webmanifest` with `name`, `short_name`, `start_url`, `display: standalone`, theme/background colors
  - [ ] Provide 192x192 and 512x512 icons in `public/icons`
  - [ ] Link manifest in `index.html`

- [ ] 4. Add Service Worker (Workbox)

  - [ ] `pnpm add workbox-window workbox-build -D`
  - [ ] Generate a service worker during build that precaches the app shell
  - [ ] Runtime caching for same-origin navigation and static assets
  - [ ] Cache-first for fonts/icons; network-first for pages with fallback
  - [ ] Register SW in the app entry point; handle update available event

- [ ] 5. Offline behavior

  - [ ] Ensure IndexedDB-backed store works offline
  - [ ] Allow creating a new entry offline and seeing it in history immediately
  - [ ] On next online, no sync is required (all local), but app remains functional

- [ ] 6. Manual QA

  - [ ] Install prompt appears or installation is available via browser menu
  - [ ] Reload while offline: history and details view still work
  - [ ] Can create a new entry offline; after refresh, it persists
  - [ ] Regenerate button is disabled when Prompt API is unavailable

- [ ] 7. Final verification
  - [ ] Lighthouse PWA checks (Installable, Offline) pass (90+ where relevant)
  - [ ] All "Definition of Done" items are checked
  - [ ] Manifest icons and app name appear correctly when installed
  - [ ] Commit and tag release (e.g., m3)

Notes

- Keep caching simple; avoid caching API calls (none in this app)
- Test PWA on mobile if possible
