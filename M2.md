## M2 — Persistence & history (+ i18n)

Goal: Move storage from localStorage to IndexedDB with a proper state layer, deliver full CRUD history, and add basic i18n support for multiple languages.

Definition of Done

- [ ] Entries persisted in IndexedDB via `localforage` or `idb`
- [ ] State managed with `zustand` and `zustand/persist` targeting IndexedDB
- [ ] Full history UI: create, read, update, delete
- [ ] Entry details page or modal is acceptable at this stage
- [ ] Basic search/filter by text (client-side)
- [ ] i18n added with language toggle and resource files (at least EN + one more)

Step-by-step Tasks

- [ ] 1. Add dependencies

  - [ ] `pnpm add zustand localforage` (or `idb` if preferred)
  - [ ] For i18n: `pnpm add i18next react-i18next`

- [ ] 2. Introduce a store layer

  - [ ] Create `src/state/entryStore.ts` using `create()` from `zustand`
  - [ ] Define types: `Entry`, `EntryUpdate`, `EntryFilter`
  - [ ] Actions: `createEntry`, `updateEntry`, `deleteEntry`, `getEntryById`, `listEntries`, `setActiveEntryId`
  - [ ] Use `zustand/persist` with a custom storage adapter for `localforage`

- [ ] 3. Migrate data from localStorage

  - [ ] On first load after upgrade, detect localStorage key `self.entries.v1`
  - [ ] If present and IndexedDB is empty, batch-insert entries then delete the old key
  - [ ] Record a small `storageVersion` flag in persisted state

- [ ] 4. History UI (CRUD)

  - [ ] Convert history list into a dedicated section with controls
  - [ ] Add a simple inline edit or an entry details modal with editable `text`, then `Save`
  - [ ] Add `Delete` with confirm dialog
  - [ ] Add `New` button that starts a blank entry

- [ ] 5. Search & filter

  - [ ] Add a search input (debounced) that filters list by text content
  - [ ] Optional chips or dropdown for time windows (e.g., last 7/30 days)

- [ ] 6. i18n setup

  - [ ] Initialize `i18next` with `en` and one more language (e.g., `de`)
  - [ ] Create `src/i18n/index.ts` and `src/i18n/locales/{en,de}.json`
  - [ ] Wrap app with `I18nextProvider` and use `useTranslation()` in components
  - [ ] Add a simple language switcher in the header
  - [ ] Externalize all user-facing strings introduced so far

- [ ] 7. Manual QA

  - [ ] CRUD works and persists across reloads
  - [ ] Search filters the list correctly
  - [ ] Language switch updates UI text live
  - [ ] No regressions to the MVP summarize flow

- [ ] 8. Final verification
  - [ ] All "Definition of Done" items are checked
  - [ ] Migration from localStorage completed or not needed
  - [ ] i18n language toggle and resources verified
  - [ ] Commit and tag release (e.g., m2)

Notes

- Keep store actions small and deterministic
- Consider lightweight input validation with Zod for entries before persistence
